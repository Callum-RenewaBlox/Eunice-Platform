# Handover: Eunice Dispatch explainer page (ai.renewablox.com/eunice)

## Goal

Put `eunice.html` live at **ai.renewablox.com/eunice**. Phase 1 is a team explainer: it shows how Eunice decides, every half-hour, how much of Scrivelsby's CHP surplus the 44 miners take and how much is exported, and how we get paid for the export. It has to be simple, succinct and visual. Phase 2 turns the same page into the live dispatch view for the site.

The page is a working prototype. Keep its content, numbers and behaviour; wire it in, tidy it up and add the scenario run-through below. Use British English.

**Scope of this session: the page only.** The dispatch package (`dispatch/`, the API and the Foreman integration) lives on branch `feature/eunice-dispatch` and is out of scope. Phase 2 below is context, not work for now.

## What the page does

Hero with four KPIs, a sticky section nav, then seven sections. One shared state object `{hp, strat, bs}` drives every control, so the hashprice toggle ($34 / $40 per PH/day) stays in sync across sections.

1. **How it works.** SVG flow: day-ahead prices, gDUoS, hashprice and expected surplus → Eunice (48 half-hours, 8-period minimum run) → setpoint → Foreman → 44 miners and grid export (SSP spill). Edge agent noted. Three one-line takeaways.
2. **Three states, not two.** Cards for *Full mining* (7.8 kW/miner), *Efficient mining + export* (6.2 kW/miner, about 75 kW exported) and *Stop & export everything*. A bar shows what each slice of the 371 kW surplus earns. Table of four settings: Efficient, Installed (7.208 kW), Full surplus (7.81 kW) and Max overclock (9.911 kW, not reachable).
3. **Decision ladder.** Export-value slider £0–140 with live outcome: mode badge, kW split (miners / cooling / export) and £ per half-hour for export-all, mine-all and Eunice. The physics in JS mirrors `dispatch/engine.py` (closed-form optimum, clamped between 6.2 kW/miner and full surplus, stop if export-all beats it).
4. **A week of decisions.** Export-value line over stacked per-half-hour columns: full = orange, efficient = purple, export = blue, red band shaded. Toggles: strategy (Eunice 3 states vs mine-or-export), minimum run 4/8/12, hashprice. Hover crosshair tooltip. Stat line: week £, full starts, half-hours per state, Eunice advantage.
5. **Trading blocks.** Grouped bars for £/yr against the no-minimum baseline and for full cycles per year, at 4/8/12 periods. Eunice in teal, mine-or-export in grey. Segmented bar for time share in each state at 8 periods. Recommendation callout and a "Show the numbers" table.
6. **Getting paid.** SSP spill explained (what we're paid, imbalance risk, fees), contract shortlist with links, fee estimates, phase-2 "real-time SSP" information ladder, gDUoS credit table 2025/26–2027/28.
7. **Next steps.** Six open items and the phase-2 API endpoints.

Footer: basis and method.

## Scenarios to run through (new: build into section 4)

These are the moments to talk the team through. All use data already in `week.json`; no new data is needed.

**Behaviour:**
- Add a row of six numbered scenario chips above the week chart, plus Previous / Next buttons and a "Whole week" reset.
- Choosing a scenario does four things:
  - sets the shared state (hashprice, minimum run, strategy);
  - zooms the week chart to the zoom range, with an hourly axis labelled every 3 hours;
  - outlines the scenario window across both panels;
  - shows a caption card under the chart.
- The caption card has a headline, the story text, and three £ figures for the window: Eunice, mine-or-export (same minimum run) and export only.
- Compute the £ in JS, per half-hour: `0.5 × (export_value × (371 − P − parasitic(P)) / 1000 + K·P^0.7)`, where P = `miner_kw` and K comes from the page model. Summed over the whole week this reproduces each variant's `value_gbp`.
- If the user changes a toggle while a scenario is open, keep the zoom and recompute the £.
- Deep links `#scenario-1` … `#scenario-6`. Left/right arrow keys step through scenarios when the chart has focus.

## Data contract

All data is inlined as two constants.

**`WEEK`** (`data/week.json`):
- `days`: 7 ISO dates (UK settlement days).
- `price[336]`: day-ahead £/MWh.
- `export_value[336]`: DA + gDUoS credit, £/MWh, no fee.
- `band[336]`: `r`/`a`/`g`.
- `variants["hp{34|40}_b{4|8|12}_{partial|binary}"]`:
  - `miner_kw[336]`;
  - `mode` (336-char string: `E` export, `P` efficient/trim, `M` full);
  - `value_gbp` (week total);
  - `starts` (off→on transitions after the first period).

**`YEAR`** (`data/year_blocks.json`): `YEAR[hp][block]` for blocks `1|4|8|12`, with:
- `partial_vs_base`, `binary_vs_base`, `partial_minus_binary` (£/yr against mine-or-export with no minimum);
- `cycles_partial`, `cycles_binary` (full start/stop cycles per year);
- `share_partial{stop,efficient,between,full}`, `share_binary{stop,full}` (share of engine-running half-hours).

**Page constants** (top of the script, object `F`):
- N 44, installed 7.208 kW / 464 TH/s, α 0.70;
- min 6.2 kW, max 9.911 kW;
- fixed 5 kW, cooler 25 kW per 381.6 kW of miner draw;
- surplus S 371 kW, GBP/USD 1.3413.

In phase 2, read these from `dispatch/sites/scrivelsby.json` (via an API field), not hard-coded.

**Deliberate differences from the live config.** Keep them, but label them on the page:
- **44 miners on the page vs 40 in `scrivelsby.json`.** Update the config to 44 when the deployment is confirmed. The live config's `rack_limit_kw` 400 must then be checked against 44 × 9.911 kW (436 kW).
- **Export margin 0 kW on the page vs 10 kW live.**
- **No offtaker fee in the dispatch figures** (fees are shown separately).

Replace it with an engine-based year run once a year of half-hourly prices is available through the Modo API (`MODO_API_KEY`, open item D4). Keep the same JSON shape. Expect fewer cycles than the current figures.

4. **Provider links** were checked on 6 Nov 2026. F&S Energy's page doesn't describe a pass-through product; it's listed as "on request".
5. **Fee estimates and the real-time SSP ladder are earlier backtests:**

## Background

- **Dispatch package:** `dispatch/` on branch `feature/eunice-dispatch`. See `dispatch/README.md` for the design, API and open decisions D1–D7.
- **Offtake:**
  - SSP spill is preferred (paid SSP per half-hour plus gDUoS, less a fee).
  - Avoid N2EX daily-average products for a peaker.
  - A hybrid (day-ahead position plus SSP) is a later option.
- **Recommended operating rule:**
  - 8-period (4-hour) minimum on full starts and stops;
  - partial dispatch down to 6.2 kW/miner (MicroBT M63S++ Low-mode floor, via power adjustment in normal mode, which avoids a reboot);
  - next-day look-ahead, so a run is only started if it pays over its whole length.
- **Data sources:**
  - Scrivelsby export MPAN 1170000388200, Mar 2025 – Mar 2026 (Sep 2025 and Jan 2026 missing);
  - EPEX GB half-hourly day-ahead and Elexon system prices, via Modo Energy;
  - NGED East Midlands HV generation gDUoS.
